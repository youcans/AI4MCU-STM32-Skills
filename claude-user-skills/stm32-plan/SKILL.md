# STM32编程任务规划Skill

## 1. 输入规范

当前工作目录为项目根目录，项目名称`<project-name>`取当前目录名称。

读取以下文件：

- `docs/requirements/proj_requirements.md`
- `docs/analysis/init_scan.md`

## 2. 输出规范

编程任务清单用于规划代码实现任务，为`stm32-code` Skill提供任务依据。

文件格式采用任务清单模板`assets/task_list.tpl.md`。

模板中的尖括号内容仅用于说明或占位，不得原样写入文件。

开发者确认后的正式编程任务清单保存至`docs/tasks/task_list.md`。

## 3. 执行步骤

### 3.1 读取输入文件

1. 读取项目任务需求文件`docs/requirements/proj_requirements.md`和初始工程分析文件`docs/analysis/init_scan.md`。
2. 如果输入文件读取失败，则进入异常出口。

### 3.2 第一阶段：生成编程任务列表

1. 根据项目任务需求和初始工程分析结果，将项目开发内容拆分为编程任务。
2. 编程任务采用`T01、T02、…`连续编号，编号同时表示建议的实施顺序。
3. 第一阶段仅生成编程任务列表，不细化编程任务。每项编程任务包括任务编号、任务名称和任务概要，任务概要说明需要完成的功能或阶段性目标。
4. 按照任务清单模板生成编程任务清单文件，仅填写编程任务列表，并保存至`docs/tasks/task_list.md`。
5. 提交开发者审阅编程任务列表，由开发者确认或使用对话交互方式提出修改意见。
6. 如果开发者提出修改意见，根据意见修改编程任务列表并再次提交审阅。

### 3.3 第二阶段：细化编程任务

1. 根据开发者确认的编程任务列表，逐项细化编程任务。
2. 每项编程任务明确任务目标、涉及文件、主要修改位置、实施要点和验证要求。
3. 主要修改位置应明确相关文件中的函数、代码区域或其它代码位置，以及该位置承担的代码职责。
4. 实施要点应说明需要完成的主要处理和关键逻辑关系，不展开具体代码设计。
5. 按照任务清单模板补充编程任务详细说明和补充说明，并保存更新后的编程任务清单。

## 4. 编程任务拆分要求

1. 编程任务应按照可独立验证的功能增量划分，每项编程任务完成后应形成明确的系统能力或阶段性能力。
2. 如果前一阶段能够独立验证，且后一阶段是在其基础上的功能扩展，应优先拆分为不同编程任务。
3. 同一功能链中共同完成一个目标的变量定义、函数实现、接口建立、文件修改和工程接入等工作，应合并为一个编程任务，不按照文件、函数或代码位置机械拆分。
4. 每项编程任务应具有明确的验证方式；编译、烧录、调试和硬件运行属于编程任务的验证方式，不单独规划为编程任务。

## 5. 边界约束

1. 仅依据项目任务需求文件和初始工程分析文件进行编程任务规划，不读取或使用其它文件。
2. 除编程任务清单外，不修改其它文件。
3. 不得自动补充或猜测无法确认的信息。
4. 不进行具体代码设计。

## 6. 出口规范

### 6.1 正常出口

编程任务规划完成并形成正式编程任务清单后进入正常出口。

如果进入正常出口，输出编程任务规划摘要，并提示：

【调用`stm32-code` Skill按编程任务清单逐项实施代码修改。】

最后调用`stm32-log` Skill，并结束本Skill。

### 6.2 异常出口

不满足正常出口条件时进入异常出口。

如果进入异常出口，输出未完成原因和当前执行状态。

最后调用`stm32-log` Skill，并结束本Skill。
