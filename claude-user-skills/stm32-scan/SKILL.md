# STM32初始工程扫描Skill

## 1. 输入规范

当前工作目录为项目根目录，项目名称`<project-name>`取当前目录名称。

读取以下文件：

- `docs/requirements/proj_requirements.md`
- `<project-name>.ioc`或`<project-name>.ioc2`
- 初始工程的构建配置文件
- 与项目目标、功能要求和硬件定义相关的源码文件和头文件

## 2. 输出规范

初始工程分析文件用于记录与项目目标和功能要求相关的初始工程状态，为编程任务规划和代码实现提供工程基础信息。

文件格式采用初始工程分析模板`assets/init_scan.tpl.md`。

模板中的尖括号内容仅用于说明或占位，不得原样写入文件。

生成的初始工程分析文件保存至`docs/analysis/init_scan.md`。

## 3. 执行步骤

### 3.1 读取输入文件

1. 读取项目任务需求文件`docs/requirements/proj_requirements.md`，获取项目目标、功能要求和硬件定义。
2. 读取当前项目实际存在的`<project-name>.ioc`或`<project-name>.ioc2`。
3. 根据实际初始工程结构，确定并读取构建配置文件，以及与项目目标、功能要求和硬件定义相关的源码文件和头文件。
4. 如果所需输入文件读取失败，则进入异常出口。

### 3.2 分析工程与构建结构

1. 分析源码文件、头文件及其组织方式。
2. 根据构建配置文件分析源码和头文件的工程接入方式。
3. 确定自定义源码和头文件的工程接入位置。

### 3.3 分析相关工程配置

1. 根据项目目标、功能要求和硬件定义，确定相关引脚、外设、DMA、中断和时钟。
2. 分析相关引脚和外设的当前配置。
3. 分析相关DMA、中断、IRQHandler和回调函数。
4. 分析相关初始化函数、句柄、全局对象和宏定义。
5. 分析程序初始化顺序、主循环和代码接入位置。
6. 判断初始工程是否具备实现项目目标和功能要求所需的硬件和工程配置条件，不判断后续代码实现所需的软件机制或资源。

### 3.4 生成初始工程分析文件

1. 根据分析结果，按照初始工程分析模板生成初始工程分析文件。
2. 对无法确认的内容，标记为未知或待确认。
3. 如果项目任务需求中的待确认事项直接影响某项工程配置是否满足功能要求，则该项工程状态结论标记为“待确认”，不得判定为“已具备”。
4. 将生成文件保存至`docs/analysis/init_scan.md`。

## 4. 边界约束

1. 仅围绕项目目标、功能要求和硬件定义，读取初始工程中与分析直接相关的构建配置文件、源码文件和头文件，不扩展读取与当前任务无关的工程文件。
2. 仅围绕项目目标、功能要求和硬件定义，并按照输出模板要求提取工程信息，不扩展分析其它内容。
3. 不得分析具体代码实现方案和函数调用方案，不得编写或修改代码。
4. 不得根据功能要求预设后续代码实现方式，也不得据此扩展分析与具体实现相关的工程资源。
5. 不得自动补充或猜测无法确认的信息。

## 5. 出口规范

### 5.1 正常出口

满足以下条件进入正常出口：

1. 初始工程分析完成并生成初始工程分析文件。

如果进入正常出口，输出分析摘要，并提示：

【调用`stm32-plan` Skill进行编程任务规划。】

最后调用`stm32-log` Skill，并结束本Skill。

### 5.2 异常出口

不满足正常出口条件时进入异常出口。

如果进入异常出口，输出未完成原因和当前执行状态。

最后调用`stm32-log` Skill，并结束本Skill。
