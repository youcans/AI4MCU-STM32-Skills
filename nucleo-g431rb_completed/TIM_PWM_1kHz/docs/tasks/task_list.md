# 编程任务清单

## 1. 编程任务列表

| 编号 | 任务名称 | 任务概要 |
|---|---|---|
| T01 | 启动 TIM2 PWM 输出 | 在现有 TIM2 配置基础上启动 PWM 输出，使 PA5（LD2）输出约 1 kHz、初始占空比 10% 的 PWM 信号，验证从定时器初始化到引脚输出的 PWM 硬件链路。 |
| T02 | 实现呼吸灯占空比周期性调度 | 基于 SysTick（HAL_GetTick）软件调度，在主循环中按约 2 秒周期将 PWM 占空比在 10%~90% 之间平滑往复变化（10%→90%→10%），驱动 LD2 呈现呼吸灯效果，且不影响 1 kHz PWM 频率。 |

## 2. 编程任务详细说明

### T01 启动 TIM2 PWM 输出

#### 任务目标

完成 T01 后，系统可输出约 1 kHz、初始占空比 10% 的 PWM 信号至 PA5，板载 LD2 以 10% 占空比亮度稳定点亮，验证 TIM2 PWM 硬件链路（定时器初始化 → 通道输出 → PA5 引脚 → LD2）已完整可用。

#### 涉及文件

- Core/Src/main.c

#### 主要修改位置

| 文件 | 函数或代码区域 | 处理内容 |
|---|---|---|
| main.c | main() 中 USER CODE BEGIN 2 / END 2 | 调用 PWM 输出启动，使 TIM2_CH1 开始输出；可同时作初始化完成确认 |

#### 实施要点

- 在时钟、GPIO、TIM2 初始化完成之后启动 TIM2 通道 1 的 PWM 输出。
- 启动时使用 CubeMX 已配置的初始参数（Prescaler=159、Period=999、Pulse=100，对应 1 kHz/10%），无需改动任何 TIM2 配置，也不改动初始化函数。
- 不引入定时器中断、DMA 等额外资源。

#### 验证要求

- 编译通过并烧录运行。
- PA5 引脚应输出约 1 kHz 方波（可用示波器/逻辑分析仪确认，或间接观察 LED）。
- LD2 应稳定点亮且亮度明显低于全亮（约 10% 占空比暗亮），无闪烁。若观察 LD2 存在高频闪烁，检查 PWM 频率是否达到 1 kHz。

### T02 实现呼吸灯占空比周期性调度

#### 任务目标

完成 T02 后，LD2 呈现呼吸灯效果：亮度由暗到亮、再由亮到暗平滑往复变化；一个完整呼吸周期（10%→90%→10%）时长约 2 秒；PWM 频率保持约 1 kHz 不变。

#### 涉及文件

- Core/Src/main.c

#### 主要修改位置

| 文件 | 函数或代码区域 | 处理内容 |
|---|---|---|
| main.c | 私有变量区（USER CODE BEGIN PV / END PV） | 定义呼吸灯调度所需的私有状态变量（如当前占空比目标、变化方向、时间基准等） |
| main.c | 主循环（USER CODE BEGIN WHILE / END WHILE 或 USER CODE BEGIN 3 / END 3） | 以 HAL_GetTick() 为时间基准的软件调度，周期性更新占空比 |
| main.c | 私有用户代码区（USER CODE BEGIN 0 / END 0）或 USER CODE BEGIN 4 / END 4 | 实现占空比更新处理的辅助函数（更新比较值、方向切换、边界处理等） |

#### 实施要点

- 呼吸灯周期：约 2 秒完成 10%→90%→10% 一个循环（半程约 1 秒，从 10% 升至 90% 或反向）。
- 占空比边界：10%~90%，对应比较值范围 Pulse=100~900（Period=999），到达边界后改变变化方向，往复循环。
- 时间基准：使用 HAL_GetTick()（SysTick 时基，已启用）在主循环中做非阻塞软件调度；不得使用阻塞式延时占用整个 CPU。
- 平滑性：变化步进与时间间隔需自行设计（如固定步进加固定时间片，或以时间为单位计算目标占空比），使亮度变化平滑无明显跳变；推荐步进与间隔组合满足约 2 秒周期并保证视觉平滑。
- 占空比更新：通过修改定时器比较值实现（对应 HAL 的比较值设置），不得改动 Prescaler/Period 以免破坏 1 kHz 频率。
- 主循环保持非阻塞：调度基于时间差判断，不因占空比更新阻塞循环。
- 不使用定时器中断、不使用额外引脚、不新增文件。

#### 验证要求

- 编译通过并烧录运行。
- LD2 亮度平滑完成 暗→亮→暗 往复循环，肉眼可见节奏约 2 秒/周期，无闪烁、无跳变。
- PWM 频率稳定为约 1 kHz（如用示波器确认，占空比随时间变化而频率不变）。
- 若观察亮度变化生硬（台阶感明显），检查步进间隔过大；若周期显著偏离约 2 秒，检查时间和步进设计。

## 3. 补充说明

- 按任务编号顺序实施：先 T01 验证 PWM 输出链路，再 T02 叠加呼吸灯调度。
- T01 是 T02 的依赖基础；T01 完成后应烧录并验证 LD2 以 10% 亮度点亮，再开始 T02。
- 呼吸灯步进与延时参数（实施要点中未固定的部分）在代码实施时自行设计，满足约 2 秒/周期与视觉平滑即可，无需额外向开发者确认。
- 已确认约束（来自初始工程分析）：占空比更新采用 SysTick 软件调度；不配置额外观测引脚；不启用 TIM2 中断或 DMA。
- 仅修改 main.c，不修改 CubeMX 生成的外设配置、不新增源文件；若后续实施中发现需要修改 .ioc 或工程配置，需先暂停并与开发者确认。
